# Octane Research Studio

Основной запуск — Docker на вашем ноутбуке: http://localhost:3001. Документы, PDF и зашифрованные подключения сохраняются в отдельном томе; приложение доступно, пока ноутбук и Docker работают. GitHub Codespaces используется для разработки: остановка по бездействию отключает адрес `app.github.dev`.

Дополнительная приватная версия: https://octane-research-studio.sf-education-4624.chatgpt.site (код в `hosted/`). Данные из Codespaces туда автоматически не переносятся.

Приватное веб-приложение: статья [Octane Rent](https://octane.rent/blog/) → аналитический текст с источниками → проверка фактов → PDF → Internet Archive, OSF, Figshare и Zenodo.

## Запуск

Для Docker нужен только установленный и запущенный Docker с Compose. Node.js на ноутбуке устанавливать не нужно.

```bash
git clone https://github.com/makkeeva/octane-research-studio.git
cd octane-research-studio
bash scripts/docker-local.sh
```

На Windows в PowerShell вместо последней команды выполните `powershell -NoProfile -File scripts/docker-local.ps1`. Docker Desktop должен использовать Linux containers. Для копии по другому пути добавьте `-BackupFile "C:\полный\путь\octane-local-backup.enc.json"`.

Скрипт задаёт локальный PUBLIC_URL, запускает приложение на порту **3001** и сохраняет существующие пароль и ключи. При первом запуске без резервной копии попросит придумать пароль приложения; ввод скрыт. Откройте **http://localhost:3001**. Если репозиторий уже скачан, выполните в его папке `git pull --ff-only`, затем `bash scripts/docker-local.sh`.

### Перенос из Codespaces

В терминале Codespaces, в папке проекта, после завершения генерации выполните:

```bash
git pull --ff-only
node scripts/data-backup.mjs export .data/octane-local-backup.enc.json
```

Скачайте `.data/octane-local-backup.enc.json` через проводник Codespaces в папку Downloads на ноутбуке. При запуске `bash scripts/docker-local.sh` копия найдётся автоматически. Введите **прежний пароль приложения Octane**, которым входили в студию. Это не пароль GitHub и не токен площадки. Перенесутся база, отчёты, PDF и сохранённые подключения; повторно вставлять ключи не нужно. Копия зашифрована AES-256-GCM с ключом из прежнего пароля. Файл не перезаписывается при повторном экспорте; для новой копии выберите другое имя и передайте её путь скрипту.

Если файл находится в другом месте:

```bash
bash scripts/docker-local.sh "/полный/путь/octane-local-backup.enc.json"
```

Существующая база в локальном томе не перезаписывается. Сохраняйте резервную копию и прежний пароль вместе с вашими обычными резервными копиями. Для другого свободного порта используйте, например, `STUDIO_PORT=3002 bash scripts/docker-local.sh`.

### Запуск без Docker

Требуется **Node.js 24+**.

```bash
cp .env.example .env
# Укажите APP_PASSWORD (минимум 12 символов) и при необходимости OPENAI_API_KEY. Ключи площадок сохраните через «Подключения» приложения.
npm ci
npm run build
npm start
```

Откройте **http://localhost:3000**, введите APP_PASSWORD. Без ключа модели доступны импорт, ручной редактор, PDF и публикация. Для автоматического поиска и переписывания откройте «Подключения → Gemini», вставьте API-ключ Google AI Studio и нажмите «Сохранить и проверить». Ключ хранится зашифрованным; перезапуск не нужен. Используется Gemini 2.5 Flash-Lite с Google Search: сначала поиск, затем структурированный отчёт. Используйте проект Free tier; доступная квота зависит от аккаунта. При HTTP 429 приложение останавливает запрос без автоматических повторов и перехода на платный API. Проверка подключения читает сведения о модели и не подтверждает квоту генерации. Источники ответа сверяются с результатами поиска, факты проверяет человек. Можно задать GEMINI_API_KEY в .env. Старый вариант OPENAI_API_KEY / OPENAI_MODEL (по умолчанию gpt-4.1) поддерживается, когда Gemini не настроен; его API оплачивается отдельно от ChatGPT.

### Управление Docker

```bash
docker compose logs --tail=100 studio
docker compose stop
docker compose up -d
```

Том `octane-research-studio_studio-data` хранит базу, PDF и подключения. Перезапуск контейнера и `docker compose down` сохраняют его; **`docker compose down -v` удаляет данные**. Политика `unless-stopped` запускает контейнер после перезапуска Docker, если вы не остановили его вручную.

### GitHub Codespaces

Контейнер устанавливает зависимости и собирает приложение. В терминале выполните `npm run setup`, придумайте пароль приложения и повторите его (ввод скрыт), затем выполните `npm start`. Настройка создаёт исключённый из Git файл .env с правами 0600, HOST=0.0.0.0 и PUBLIC_URL порта 3000; уже существующий пароль не заменяется. Откройте порт 3000 во вкладке «Порты» и оставьте его приватным. Токены площадок добавляются через «Подключения» → «Сохранить и проверить» и сохраняются в зашифрованном виде; OpenAI API key задаётся в Codespaces Secrets либо .env. При ручной настройке PUBLIC_URL должен совпадать с HTTPS-адресом проброшенного порта.

### VPS / постоянный доступ

GitHub хранит исходный код; полноценный сервер запускается на VPS или контейнерном хостинге. GitHub Pages не выполняет серверный код. Используйте Compose и HTTPS reverse proxy (Caddy/Nginx). Задайте PUBLIC_URL точному внешнему origin, например `https://research.example.com`, и сохраняйте исходный Host в proxy. Compose публикует порт только на loopback. Если reverse proxy находится в другом контейнере, подключите его к общей сети и адресуйте `studio:3000`; не открывайте backend напрямую.

Приложение рассчитано на одного владельца. Сессии действуют 12 часов и переживают перезапуск сервера; в базе хранятся только их HMAC-хэши. Изменение APP_PASSWORD прекращает действие существующих сессий. Для публичного URL используется Secure cookie. Для AI-запросов reverse proxy должен поддерживать timeout более 4 минут.

## Рабочий процесс

1. Загрузите каталог Octane либо вставьте ссылку на статью. Если сайт ограничивает доступ, добавьте ссылку и текст вручную.
2. Укажите реального автора и язык. AI использует Responses API с web search, ищет первичные источники и создаёт аналитический черновик, реестр фактов и библиографию.
3. Откройте ссылки и сверьте каждое утверждение: числа, единицы, дату, географию, год модели. Отметьте проверку каждого факта. Неподтверждённые и противоречивые утверждения блокируют публикацию.
4. Выберите лицензию, подтвердите права и общую проверку. PDF содержит активную исходную ссылку Octane, раскрытие AI, ограничения, вклад автора, библиографию и реестр фактов. Кириллица поддерживается. Непроверенный PDF помечается черновиком.
5. Подготовьте выбранные площадки и затем опубликуйте. После подготовки публикаций документ замораживается; правки требуют копии.

## Доступ к площадкам

| Площадка | Ключи | Публикация |
| --- | --- | --- |
| Internet Archive | [S3 Access + Secret Key](https://archive.org/account/s3.php) | Подготовка локальная; финальная загрузка сразу публичная. Сначала статус очереди; после проверки Metadata API — опубликовано. |
| OSF | [Personal Access Token](https://osf.io/settings/tokens/) с правами создавать/изменять проекты и файлы | На документ создаётся отдельный приватный проект. PDF загружается через WaterButler; финальный шаг делает только этот проект public. Это не регистрация исследования или preprint. |
| Figshare | [Personal token](https://figshare.com/account/applications) | Приватная запись, multipart upload, отдельная публикация. Категория и лицензия выбираются из API-справочников. Лицензия должна совпадать с PDF. |
| Zenodo | [Personal token](https://zenodo.org/account/settings/applications/tokens/new/) с deposit:write и deposit:actions | Черновик отчёта, PDF, отдельная публикация. Требуется самостоятельный исследовательский вклад человека. |

Email `seo@mbear.ae` сам по себе не даёт API-доступ. Пароли от площадок не нужны. В «Подключениях» вставьте ключи и нажмите «Сохранить» или «Сохранить и проверить». После успешного сохранения поля очищаются, а сервер использует сохранённые ключи при публикации. Ключи переживают обновление страницы, выход и перезапуск; они зашифрованы AES-256-GCM в SQLite и не возвращаются в браузер, экспорт документов или историю публикаций. Ключ шифрования выводится из APP_PASSWORD через scrypt с отдельной случайной солью. При изменении APP_PASSWORD старые подключения нужно сохранить заново либо вернуть прежний пароль; резервная копия DATA_DIR открывается с прежним APP_PASSWORD. Переменные ARCHIVE_ACCESS_KEY, ARCHIVE_SECRET_KEY, OSF_TOKEN, FIGSHARE_TOKEN, ZENODO_TOKEN остаются альтернативным способом настройки.

OSF: лицензия включается в PDF; лицензирование самого проекта через настройки OSF отдельно не автоматизировано. При необходимости установите его в интерфейсе OSF.

На всех четырёх карточках есть «Сохранить» и «Сохранить и проверить», инструкции получения ключей и статус последней проверки. Проверка выполняет только GET к авторизованному профилю или списку записей аккаунта. Она подтверждает авторизацию, но не права на создание проекта, загрузку или публикацию. Если проверка не проходит, сохранённый ключ остаётся на сервере. Несохранённые поля остаются только в памяти вкладки; браузер предупреждает перед её закрытием.

[OSF объявил прекращение создания новых проектов через API с 16 ноября 2026 года и переход проектов в режим чтения с 19 февраля 2027 года](https://help.osf.io/article/744-osf-projects-api-impact). Адаптер создаёт отдельный проект для каждого отчёта, поэтому после первой даты этот способ публикации в OSF не будет работать. Для последующей публикации используйте подходящие материалы для других площадок.

## Исследовательские требования

Формальная стилистика и ссылки не превращают рекламную статью в научное исследование. [Zenodo запрещает рекламные материалы и AI-обзоры без существенного самостоятельного анализа](https://support.zenodo.org/help/en-gb/2-safelisting-spam/141-what-content-do-you-consider-spam). Приложение требует описание выполненного человеком анализа для Zenodo, однако длина описания не доказывает пригодность: автор оценивает соответствие правилам. Площадки могут отклонить или удалить материал.

AI не указывается автором; документ не объявляется рецензируемым или эмпирическим. Коммерческий первоисточник и помощь AI раскрываются. Ссылки ответа AI сверяются с источниками текущего поиска; это проверка происхождения ссылки, а не автоматическое доказательство утверждения. Финальную проверку выполняет человек. Недостающие реальные цифры не заменяются выдуманными.

## Данные и восстановление

DATA_DIR (по умолчанию `.data`) содержит `studio.sqlite`, его WAL-файлы и `pdf/`. Делайте backup после остановки сервера либо штатным SQLite backup. Не коммитьте .env или .data.

Внешние ID сохраняются по ходу отправки. Повторные клики не создают запись заново. При ошибке загрузка не повторяется автоматически: используйте «Проверить внешний статус» и ссылку на площадку. Эта проверка подтверждает публичную запись, но не чинит неполную загрузку. Незавершённые multipart uploads требуют ручной проверки в сервисе. Если создание записи произошло, но ответ с ID потерялся, сначала проверьте аккаунт; не отправляйте копию вслепую.

Правки текста сбрасывают фактологические отметки. Генерация выполняется на сервере после короткого запроса запуска. Её этап и ошибка сохраняются в SQLite и отображаются рядом с кнопкой; обновление страницы не отменяет работу. Повторное нажатие во время активной генерации возвращает её текущий статус. Перезапуск сервера помечает незавершённые задачи как прерванные. Для большого потока потребуется отдельная очередь рабочих процессов.

## Проверки

```bash
npm ci
npm run check
npm run build
npm test
```

GitHub Actions выполняет проверки на push/PR. Ручной workflow `Build Docker image` собирает образ и публикует его в GHCR; он не развёртывает сервер и не публикует статьи.

Тесты не тратят OpenAI API и не публикуют материалы. Они проверяют сервер, сохранение после перезапуска, блокировку непроверенных фактов, PDF и адаптеры на mock-ответах. Реальная отправка на четыре площадки требует ваших токенов и отдельной проверки. Dockerfile предоставлен; для проверки контейнера нужен Docker.

## Код

`src/server.ts` — HTTP, авторизация и SQLite; `lib/research/` — импорт, AI, PDF, валидация и API-адаптеры; `public/` — интерфейс без CDN; `fonts/` — DejaVu Sans с лицензией. Приложение не зависит от ChatGPT Sites и переносится на любой сервер с Node.js 24 и постоянным диском.
