# Octane Research Studio

Приватное веб-приложение: статья [Octane Rent](https://octane.rent/blog/) → аналитический текст с источниками → проверка фактов → PDF → Internet Archive, OSF, Figshare и Zenodo.

## Запуск

Требуется **Node.js 24+** либо Docker Compose.

```bash
cp .env.example .env
# Укажите APP_PASSWORD (минимум 12 символов), OPENAI_API_KEY и токены площадок.
npm ci
npm run build
npm start
```

Откройте **http://localhost:3000**, введите APP_PASSWORD. Без ключа модели доступны импорт, ручной редактор, PDF и публикация. Для автоматического поиска и переписывания нужен OPENAI_API_KEY; API оплачивается отдельно от ChatGPT. Модель задаётся OPENAI_MODEL, по умолчанию gpt-4.1.

### Docker

```bash
cp .env.example .env
# Заполните APP_PASSWORD и нужные ключи.
docker compose up -d --build
```

Откройте http://localhost:3000. Том `studio-data` хранит документы. `docker compose down` сохраняет его; `down -v` удаляет данные.

### GitHub Codespaces

Контейнер устанавливает зависимости и собирает приложение. В терминале выполните `npm run setup`, придумайте пароль приложения и повторите его (ввод скрыт), затем выполните `npm start`. Настройка создаёт исключённый из Git файл .env с правами 0600, HOST=0.0.0.0 и PUBLIC_URL порта 3000; уже существующий пароль не заменяется. Откройте порт 3000 во вкладке «Порты» и оставьте его приватным. Токены площадок можно добавить через раздел «Подключения» приложения; OpenAI API key задаётся в Codespaces Secrets либо .env. При ручной настройке PUBLIC_URL должен совпадать с HTTPS-адресом проброшенного порта.

### VPS / постоянный доступ

GitHub хранит исходный код; полноценный сервер запускается на VPS или контейнерном хостинге. GitHub Pages не выполняет серверный код. Используйте Compose и HTTPS reverse proxy (Caddy/Nginx). Задайте PUBLIC_URL точному внешнему origin, например `https://research.example.com`, и сохраняйте исходный Host в proxy. Compose публикует порт только на loopback. Если reverse proxy находится в другом контейнере, подключите его к общей сети и адресуйте `studio:3000`; не открывайте backend напрямую.

Приложение рассчитано на одного владельца. Сессии действуют 12 часов, хранятся в памяти и сбрасываются при перезапуске. Для публичного URL используется Secure cookie. Для AI-запросов reverse proxy должен поддерживать timeout более 4 минут.

## Рабочий процесс

1. Загрузите каталог Octane либо вставьте ссылку на статью. Если сайт ограничивает доступ, добавьте ссылку и текст вручную.
2. Укажите реального автора и язык. AI использует Responses API с web search, ищет первичные источники и создаёт аналитический черновик, реестр фактов и библиографию.
3. Откройте ссылки и сверьте каждое утверждение: числа, единицы, дату, географию, год модели. Отметьте проверку каждого факта. Неподтверждённые и противоречивые утверждения блокируют публикацию.
4. Выберите лицензию, подтвердите права и общую проверку. PDF содержит активную исходную ссылку Octane, раскрытие AI, ограничения, вклад автора, библиографию и реестр фактов. Кириллица поддерживается. Непроверенный PDF помечается черновиком.
5. Подготовьте выбранные площадки и затем опубликуйте. После подготовки публикаций документ замораживается; правки требуют копии.

## Доступ к площадкам

| Площадка | Ключи | Публикация |
| --- | --- | --- |
| Internet Archive | [S3 Access + Secret Key](https://archive.org/account/s3.php) | Подготовка локальная; финальная загрузка сразу публичная. Сначала статус очереди; после проверки Metadata API — опубликовано. |
| OSF | [Personal Access Token](https://osf.io/settings/tokens/) с правами создавать/изменять проекты и файлы | На документ создаётся отдельный приватный проект. PDF загружается через WaterButler; финальный шаг делает только этот проект public. Это не регистрация исследования или preprint. |
| Figshare | [Personal token](https://figshare.com/account/applications) | Приватная запись, multipart upload, отдельная публикация. Категория и лицензия выбираются из API-справочников. Лицензия должна совпадать с PDF. |
| Zenodo | [Personal token](https://zenodo.org/account/settings/applications/tokens/new/) с deposit:write и deposit:actions | Черновик отчёта, PDF, отдельная публикация. Требуется самостоятельный исследовательский вклад человека. |

Email `seo@mbear.ae` сам по себе не даёт API-доступ. Пароли от площадок не нужны. Введённые в UI ключи живут только в памяти вкладки, передаются вашему серверу и не сохраняются в документах или браузерном хранилище. Для постоянного доступа задайте ARCHIVE_ACCESS_KEY, ARCHIVE_SECRET_KEY, OSF_TOKEN, FIGSHARE_TOKEN, ZENODO_TOKEN в .env.

OSF: лицензия включается в PDF; лицензирование самого проекта через настройки OSF отдельно не автоматизировано. При необходимости установите его в интерфейсе OSF.

## Исследовательские требования

Формальная стилистика и ссылки не превращают рекламную статью в научное исследование. [Zenodo запрещает рекламные материалы и AI-обзоры без существенного самостоятельного анализа](https://support.zenodo.org/help/en-gb/2-safelisting-spam/141-what-content-do-you-consider-spam). Приложение требует описание выполненного человеком анализа для Zenodo, однако длина описания не доказывает пригодность: автор оценивает соответствие правилам. Площадки могут отклонить или удалить материал.

AI не указывается автором; документ не объявляется рецензируемым или эмпирическим. Коммерческий первоисточник и помощь AI раскрываются. Ссылки ответа AI сверяются с источниками текущего поиска; это проверка происхождения ссылки, а не автоматическое доказательство утверждения. Финальную проверку выполняет человек. Недостающие реальные цифры не заменяются выдуманными.

## Данные и восстановление

DATA_DIR (по умолчанию `.data`) содержит `studio.sqlite`, его WAL-файлы и `pdf/`. Делайте backup после остановки сервера либо штатным SQLite backup. Не коммитьте .env или .data.

Внешние ID сохраняются по ходу отправки. Повторные клики не создают запись заново. При ошибке загрузка не повторяется автоматически: используйте «Проверить внешний статус» и ссылку на площадку. Эта проверка подтверждает публичную запись, но не чинит неполную загрузку. Незавершённые multipart uploads требуют ручной проверки в сервисе. Если создание записи произошло, но ответ с ID потерялся, сначала проверьте аккаунт; не отправляйте копию вслепую.

Правки текста сбрасывают фактологические отметки. Для больших потоков и работы без открытой вкладки потребуется фоновая очередь; текущая AI-генерация идёт в HTTP-запросе до 4 минут.

## Проверки

```bash
npm ci
npm run check
npm run build
npm test
```

GitHub Actions выполняет проверки на push/PR. Ручной workflow `Build Docker image` собирает образ и публикует его в GHCR; он не развёртывает сервер и не публикует статьи.

Тесты не тратят OpenAI API и не публикуют материалы. Они проверяют сервер, сохранение после перезапуска, блокировку непроверенных фактов, PDF и адаптеры на mock-ответах. Реальная отправка на четыре площадки требует ваших токенов и отдельной проверки. Dockerfile предоставлен; для проверки контейнера нужен Docker.

## Код

`src/server.ts` — HTTP, авторизация и SQLite; `lib/research/` — импорт, AI, PDF, валидация и API-адаптеры; `public/` — интерфейс без CDN; `fonts/` — DejaVu Sans с лицензией. Приложение не зависит от ChatGPT Sites и переносится на любой сервер с Node.js 24 и постоянным диском.
